# curly-adventure

A text-based adventure game scaffolding written in TypeScript. No theme or real content yet — just generic placeholder rooms, items, and a working command parser.

The pre-production build is running at [https://curly-adventure.netlify.app/](https://curly-adventure.netlify.app/).
[![Netlify Status](https://api.netlify.com/api/v1/badges/f6cbf486-1e89-4b58-ac83-d3e74fcc8f72/deploy-status)](https://app.netlify.com/projects/curly-adventure/deploys)

## Project structure

```
src/
  types/        Room and Item interfaces
  engine/       Parser (command → ParsedCommand) and GameState
  data/         Placeholder rooms and items
  main.ts       Browser entry point
  __tests__/    Unit tests
public/
  index.html    Game UI
  style.css     Terminal-style styles
  bundle.js     Generated by the build (git-ignored)
```

### Dependency maintenance

Commit `package.json` and `package-lock.json` together after dependency changes.
Use npm to regenerate the lockfile; do not edit resolved versions by hand or use
`--force` / `--legacy-peer-deps` to bypass compatibility checks.

TypeScript currently stays on 5.9, which works with the existing configuration
and ts-jest's `>=4.3 <7` peer range. TypeScript 7 must wait for explicit support
from ts-jest (or a separately validated transformer migration). Review compiler
major updates together with the Jest transformer and webpack loader.

For a blocked transitive update, use `npm audit`, `npm explain <package>`, and
`npm ls <package> --all` to identify every installed copy and its parent constraints.
Try compatible lockfile updates first (`npm audit fix` for advisory fixes), then
upgrade the owning parent. Only consider a scoped override after validating
compatibility, with an upstream tracking issue and a removal condition.

The current lockfile retains `glob@10.5.0` under `babel-plugin-istanbul` →
`test-exclude@7`. It is deprecated. `test-exclude@8` uses glob 13, but its parent
currently requires version 7; wait for a compatible upstream release rather
than forcing a cross-major override. BrowserSync's affected transitive packages
were patched within their existing ranges, so no replacement is needed.

#### Temporary audit exception

Run `npm run audit` for the CI audit policy; `npm audit` remains available for
the unfiltered report. The gate prints the full report and temporarily accepts
only [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4)
in `deepmerge` and its attributable low-severity Jest dependency findings.
All other advisories, increased severities, audit execution errors, malformed
reports, and unresolved or cyclic dependency chains fail the gate.

- **Owner:** repository maintainers; tracking: [PR #56](https://github.com/tlxo/curly-adventure/pull/56)
  and the advisory above.
- **Expiry:** 2026-11-28 at 00:00 UTC; the gate fails after expiry, even without findings.
- **Rationale:** no patched deepmerge release was available when approved on
  2026-10-29. Jest uses it to merge repository-controlled test configuration,
  not browser gameplay input. This limits exposure but does not fix the issue.
  The six findings share one underlying advisory. Jest 25 would break the
  current ts-jest peer requirements; older deepmerge versions lose security guards.
- **Removal:** upgrade to a compatible upstream fix, verify the full dependency
  tree and clean raw audit, remove the exception/gate and its tests, and restore
  CI to `npm audit`. Review upstream availability before expiry; do not extend
  automatically or introduce a blanket severity threshold.

Dependabot groups testing and bundler patch/minor version updates separately;
major updates remain individual changes for compatibility review. Security
updates have their own group. Repository administrators should ensure Dependabot
alerts and security updates are enabled in repository settings, and require the
`validate` and dependency-review checks before merging.

PR validation runs a clean install, peer-tree check, type-check, tests, production
build, audit (including development dependencies), and Docker build. After changes
to BrowserSync, also smoke-test the Docker proxy and automatic reload workflow below.
Docker, Netlify, and PR validation all use Node.js 22.

## Running locally with Docker

```bash
docker compose up --build
```

Open [http://localhost:8080](http://localhost:8080) in your browser.

Re-run with `--build` any time the `Dockerfile` changes or after updating npm dependencies.

### Live-reload during development

`public/bundle.js` is git-ignored. The `docker-compose.dev.yml` overlay mounts `./public` into the nginx container, so webpack output is served immediately without restarting Docker. The first webpack build will create `public/bundle.js` once you start the workflow below; nginx will begin serving it as soon as it exists — no prior local build required.

**Step 1** — start Docker with the dev overlay in one terminal:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up
```

**Step 2** — in another terminal, run the dev auto-refresh workflow:

```bash
npm run dev:docker
```

This command runs both:

- webpack in watch mode (rebuilds `public/bundle.js` on save)
- BrowserSync proxy with automatic browser reload

Open [http://localhost:3000](http://localhost:3000) while developing. BrowserSync proxies the nginx container on `localhost:8080` and refreshes whenever files in `public/` change.

If you only want rebuilds (without auto-refresh), use:

```bash
npm run dev
```

For a one-off build:

```bash
npm run build
```

Use Docker `--build` only when the `Dockerfile` or dependencies change.

## Deploying to Netlify

Connect the repository to Netlify. The `netlify.toml` at the root configures:

- **Build command**: `npm run build`
- **Publish directory**: `public`

Netlify will run the build and serve the `public/` directory as a static site.

## Supported commands (in-game)

| Command | Shorthand | Description |
|---------|-----------|-------------|
| `look` | `l` | Describe the current room |
| `look at <item>` | | Look at a specific item |
| `go <direction>` | `n s e w u d` | Move in a direction |
| `take <item>` | `get`, `pick` | Pick up an item |
| `drop <item>` | `put` | Drop a carried item |
| `inventory` | `inv`, `i` | List carried items |
| `examine <item>` | `x`, `ex`, `inspect` | Examine an item closely |
| `use <item>` | | Use an item |
| `use <item> on <item>` | | Use one item on another item |
| `help` | `?` | Show command reference |
| `quit` | `exit`, `q` | Quit the game |
